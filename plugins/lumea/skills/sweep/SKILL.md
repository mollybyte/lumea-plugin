# Sweep

Аргумент: `$ARGUMENTS` — правило. Процесс — `${CLAUDE_PLUGIN_ROOT}/skills/lumea/reference/workflows.md`, раздел «Sweep». Скилл выполняется в отдельном форке агентом `analyst` — по ходу выполнения переспросить пользователя нельзя, форк возвращает один финальный результат; вопрос пользователю задаёт основной разговор уже после этого результата.

1. Разобрать правило на **выборку** (статус, проект, канал, приоритет, теги, условие по `lastMessage`/`created`, кто писал последним) и **действие** (закрыть; приоритет; добавить/снять тег; написать текст; только показать). «Без ответа», «зависло», «ждут» — это `status: unanswered` (последним писал клиент), уточнять это не нужно. Правило нельзя понять однозначно — не гадать: вместо таблицы вернуть один уточняющий вопрос как результат скилла и на этом остановиться.
2. `export_tickets { limit: 200 }` с фильтрами, продолжая по `nextCursor`, пока не кончится или не набрано 5 страниц (1000 строк) — тот же предел, что в `groups`/`case`: вызов на весь объём сразу ответ MCP не пропустит. Если после 5-й страницы `nextCursor` всё ещё не `null` — предупредить, что просмотрены 1000 самых активных тикетов, и предложить сузить правило. Условия по датам и «кто писал последним» проверять локально (для «клиент не отвечает N дней после нашего ответа» нужно последнее сообщение — при выборке ≤ 100 тикетов проверить `get_ticket_messages { ticketId, limit: 3 }`, при большей — сказать, что проверено по `lastMessage`, и предложить сузить).
3. Вернуть в основной разговор: таблицу (до 50 строк, остальное числом), полный список uuid, **точное действие** (инструмент, поле, значение, число тикетов) и готовую строку для подтверждения. Например: «Выполнить `bulk_update_tickets` · `status: closed` · 143 тикета?».
4. Основной разговор показывает эту строку, спрашивает «Выполнить?» и после «да» вызывает `bulk_update_tickets` / `bulk_send_messages` пачками по 200; при `nextIndex` — продолжать с `ticketIds.slice(nextIndex)` (или `items.slice(nextIndex)`), как в `case`. Отчёт по `failed` поштучно.
5. Действие «только показать» — на шаге 3 остановиться, вопроса не давать.

Агент выборки инструментов записи не имеет — выполнение всегда в основном разговоре, после «да».
