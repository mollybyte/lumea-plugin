# Клиент

Аргумент: `$ARGUMENTS` — строка поиска.

1. Если `$ARGUMENTS` — uuid, вызвать сразу `get_client { clientId: $ARGUMENTS }`, поиск не нужен. Иначе `search { query: $ARGUMENTS, limit: 5 }` — инструмент ищет и тикеты, и клиентов, из ответа брать только `clients`. Ровно один клиент — продолжить; несколько — показать список (имя, username) и спросить, какой; ноль — сказать, что не найден, и предложить искать по другому полю (email вместо имени, telegram id).
2. `get_client { clientId }` → имя, username, контакты, дата регистрации, блокировка (если есть — когда заблокирован; ответ содержит только `blockedAt`, без срока действия).
3. `get_client_tickets { clientId, perPage: 20 }` → таблица: ref (`#` + первые 8 символов id, первая группа uuid), проект (`project.name`), статус, заголовок, дата последнего сообщения (`lastMessageAt`). Поля `summary` в ответе нет — не пишет ли клиент третий раз об одном и том же, определять по совпадению заголовков самому. Число открытых сейчас — один вызов `list_tickets { clientId, perPage: 100 }` (по умолчанию без закрытых) и посчитать длину `tickets`; при `hasMore: true` не подбирать точное число, сказать «не менее N».
4. `get_client_external { clientId, projectType }` — по одному вызову на каждый тип проекта, встретившийся в `project.type` тикетов из шага 3 (без повторов); если тикетов нет — спросить, в каком проекте искать, и взять его `type` из `list_projects` по имени. `includePayments: true` только если спросили про оплату. Подписка, срок, автоплатёж — только отсюда.

Вывод — карточка в 10–15 строк, без переписки. Если попросили «заблокировать»/«разблокировать» — показать клиента, спросить срок (`24h`/`7d`/`permanent` — по умолчанию у `block_client` `permanent`, поэтому при незаданном сроке переспросить, а не блокировать навсегда молча) и «да», и только потом `block_client { clientId, duration }` / `unblock_client`. Внешние действия (`run_external_action`) — только по явной просьбе и после подтверждения; список доступных действий взять из ответа `get_client_external`; если у клиента несколько аккаунтов в проекте — спросить, какой (`accountIdentifier`), не выбирать самому.
