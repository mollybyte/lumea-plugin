# Быстрые ответы

Аргументы: `$ARGUMENTS` — подкоманда, shortcut и, если нужно, проект. Быстрый ответ — строка с `shortcut` (без `/`, в нижнем регистре), текстом, переменными `{NAME}` (подставляются при отправке) и необязательным списком каналов. Область — **проект** или **глобально** (виден во всех проектах); один shortcut может существовать и там и там, проектный при отправке важнее.

**Область и проект.** `list_quick_replies { projectName }` отдаёт проектные плюс глобальные; без `projectName` — только глобальные. Имя проекта — из `list_projects`, не угадывать. Если проект в запросе не назван, а shortcut есть в нескольких проектах — показать варианты и спросить.

**Shortcut в запросе** может прийти как `/reinstall`, `reinstall` или «квик про переустановку» — во втором случае искать по тексту в списке и, если нашлось больше одного, спросить.

**Вход инструментов.** Ведущий `/` в `shortcut` можно не срезать — сервер нормализует сам. `channels` — только если пользователь просит ограничить каналы; в `update_quick_reply` `channels: null` снимает ограничение. `id` для `update_quick_reply` и `delete_quick_reply` — из строки `list_quick_replies`; в `delete_quick_reply` передавать и `shortcut` — сервер сверит его со строкой и откажет при расхождении.

## list

`list_quick_replies { projectName? }` → таблица: shortcut · область (проект / глобально) · каналы (пусто — все) · начало текста (первые ~60 символов, переносы схлопнуть) · переменные. Отсортировать по shortcut. Без проекта в запросе показать глобальные и предложить назвать проект.

## show

Найти строку (см. «Shortcut в запросе»), вывести целиком: shortcut, область, каналы, `updatedAt`, полный текст без сокращений, список переменных `{NAME}` и число файлов (`mediaCount`; файлы через MCP не читаются и не меняются — только в дашборде).

## new

1. Собрать shortcut, текст, область (проект или глобально) и каналы из запроса; чего не хватает — спросить одним сообщением. Перед созданием — `list_quick_replies` той же области: занятый shortcut показать и предложить другой, а не пробовать создать.
2. Показать целиком, что будет создано: shortcut, область, каналы, текст в блоке кода. Спросить: «Сохранить?»
3. Только после «да» — `create_quick_reply { projectName?, shortcut, text, channels? }`. Ошибка «уже занят» — предложить другой shortcut, не менять область молча.

## edit

1. Найти строку и показать текущий текст.
2. Новый текст дан явно — взять его. Дана только правка («добавь строку про перезагрузку», «убери второй абзац») — составить итоговый текст самому, сохранив язык, тон и переменные оригинала.
3. Показать **итоговый текст целиком** в блоке кода и diff с текущим (что убрано, что добавлено — построчно). Спросить: «Сохранить?»
4. Только после «да» — `update_quick_reply { id, text }` (и `shortcut`/`channels`, если менялись). В ответе показать обновлённую строку. Без «да» ничего не вызывать.

## delete

Показать строку целиком (shortcut, область, полный текст, число файлов) и спросить: «Удалить быстрый ответ `<shortcut>` из <область>? Файлы удалятся вместе с ним, это необратимо». Только после «да» — `delete_quick_reply { id, shortcut }`.

## Правила

- Ни один из `create_quick_reply`, `update_quick_reply`, `delete_quick_reply` не вызывается без явного «да» в ответ на показанный текст; хук плагина спросит ещё раз — это страховка, а не замена показа.
- В тексте ответа клиенту не оставлять служебных пометок и незаполненных `{{…}}`; переменные быстрого ответа — `{NAME}` в верхнем регистре, их не подставлять и не «чинить».
- `Недостаточно прав: нужен ключ quick_reply.create` (`.update`, `.delete`) — назвать право и предложить попросить его у администратора на странице ролей.
