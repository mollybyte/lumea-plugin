# Issue из кейса или тикета

Аргументы: `$ARGUMENTS`. Процесс — `${CLAUDE_PLUGIN_ROOT}/skills/lumea/reference/workflows.md`, раздел «Issue из кейса».

Номер issue во втором аргументе — `42` или `#42` (`!42` тоже принимается: в GitLab `!` означает MR, но пользователи так пишут).

1. Тикеты: кейс — `list_tickets { tags: ['case:<slug>'], perPage: 100 }` (`hasMore: true` → повторить с `page: 2` и дальше, пока не `false`); тикет — один, id прямо из ref/uuid/ссылки. Показать список (ref, клиент, заголовок) — он нужен независимо от дальнейшего выбора (привязка к существующему issue или создание нового).
2. Головной тикет: один тикет — он и есть головной. Кейс — среди 3–5 самых свежих по `lastMessageAt` вызвать `get_ticket_messages { ticketId, limit: 30 }` (не `get_ticket_context` по всем сразу — тикетов в кейсе может быть до сотни, это тяжелее) и выбрать тот, где больше вложений и деталей.
3. Если передан номер issue — сразу к шагу 6 с этим номером (список из шага 1 уже показан, вторая проверка не нужна).
4. `find_related_issues { ticketId: <головной> }` → показать: заголовок черновика, метки, кандидаты (iid, заголовок, вердикт `duplicate`/`related`, причина, ссылка). При `degraded: true` — предупредить, что поиск в GitLab не ответил и кандидаты только локальные.
5. Спросить: «Привязать к #N» / «Создать новый» — ждать выбора. Черновик заголовка и тела можно показать и поправить по просьбе (передать `title`/`markdown` в вызов).
6. Существующий: `link_issue { ticketId, iid }` для каждого тикета; `alreadyLinked: true` — не ошибка, отметить. Новый: `create_issue_from_ticket { ticketId: <головной>, force: <true, если кандидаты были и пользователь их отверг>, title?, markdown?, attachmentMessageIds? }`; `created: false` (сервер нашёл похожее — в ответе `reason` и `candidates`, поля `stop` у этого инструмента нет, оно только у `find_related_issues`) — показать кандидатов и вернуться к шагу 5; затем `link_issue` с полученным `iid` для остальных тикетов.
7. Отчёт: ссылка на issue, сколько тикетов привязано, ошибки поштучно. Напомнить, что тег `issue#N` появится на тикетах сам.

Ничего не создавать и не привязывать до явного выбора пользователя.
