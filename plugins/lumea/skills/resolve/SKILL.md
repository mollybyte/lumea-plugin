# Resolve — волна закрыта

Аргументы: `$ARGUMENTS` — slug кейса или номер issue (`42`, `#42`; `!42` тоже принимается — в GitLab `!` означает MR, но пользователи так пишут), затем суть фикса (что сделано, что нужно от клиента). Процесс — `${CLAUDE_PLUGIN_ROOT}/skills/lumea/reference/workflows.md`, раздел «Resolve».

1. Выборка:
   - Кейс: `list_tickets { tags: ['case:<slug>'], includeClosed: true, perPage: 100 }` (`hasMore: true` → повторить с `page: 2` и дальше, пока не `false`); ref — `#` + первые 8 символов `id`, первая группа uuid (отдельного поля нет), имя клиента — прямо из ответа (`tickets[].client.name`), отдельно не искать.
   - Issue (`#iid`): нужен проект — в `list_issue_tickets` он обязателен. Если проект назван в `$ARGUMENTS` — использовать его; иначе `list_projects`: один проект — взять его, несколько — спросить, в каком искать `#iid`, и ждать ответа. Затем `list_issue_tickets { projectName, iid }` (`tickets[]` с `ticketRef`, `status`, `clientName`, `lastClientText`).

   В обоих случаях тикеты со `status: 'closed'` в рассылку не включать, показать их числом отдельно.

2. Язык клиента: для issue — по `lastClientText` из `list_issue_tickets` (переписку не читать; пустой `lastClientText` — язык проекта по умолчанию, русский); для кейса — `get_ticket_context` только по 3–5 самым содержательным тикетам, остальным `get_ticket_messages { ticketId, limit: 3 }` (правило лимитов справочника `lumea`: контекст по всему кейсу не читать). Текст: что было, что сделали, что нужно сделать клиенту; без сроков и обещаний, если их не дали. Один шаблон на язык, обращение по имени клиента (`clientName` у issue, `client.name` у кейса).
3. Таблица «ref · клиент · язык · текст» и вопрос: «Отправить N клиентам?» — ждать «да». Хук плагина покажет подтверждение ещё раз — это нормально.
4. `bulk_send_messages { items }`; при `nextIndex` — продолжить с него (`items.slice(nextIndex)`). Отчёт: отправлено, недоставленные поштучно.
5. Отдельно спросить: «Закрыть эти N тикетов?» → после «да» `bulk_update_tickets { ticketIds, status: 'closed' }` (с продолжением по `nextIndex`: `ticketIds.slice(nextIndex)`, как в `case`). Затем, для кейса: «Снять тег `case:<slug>`?» → `bulk_update_tickets { ticketIds, removeTags: ['case:<slug>'] }` (та же логика продолжения).

Три подтверждения — три отдельных вопроса; ни одно не подразумевает следующее.
