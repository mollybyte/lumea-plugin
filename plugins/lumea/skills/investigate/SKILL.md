# Расследование

Аргумент: `$ARGUMENTS` — slug кейса, ref тикета или свободное описание проблемы. Этот скилл выполняется в отдельном форке и не видит скилл `case`, поэтому резолвит аргумент сам:

1. **Определить `$ARGUMENTS` и собрать материал.**
   - Полный uuid или ссылка на тикет — id брать прямо из строки.
   - Короткий id тикета — 4–32 hex-символа (с `#` или без) — резолвить через `search { query: $ARGUMENTS, limit: 5 }` до полного uuid.
   - Иначе, если строка похожа на slug (латиница, цифры, дефис, до 32 символов) — это кейс: `list_tickets { tags: ['case:<slug>'], perPage: 100 }`; пусто — сказать «кейса `<slug>` нет» и остановиться, дальше не пробовать.
   - Иначе (свободный текст, не slug и не ref) — `search { query: $ARGUMENTS.slice(0, 200), limit: 5 }` (`query` ограничен 200 символами — длинный текст обрезать), взять из `tickets` 3–5 записей.

   Кейс: `get_ticket_context` для 3–5 самых содержательных тикетов из найденного списка (больше вложений и деталей) и все файлы из `.lumea/cases/<slug>/` (если папки нет — сказать, что логи не собраны, и продолжать по переписке). Тикет или свободный текст: `get_ticket_context` + `get_message_media` для вложений по каждому найденному тикету.

2. **Факты.** Выписать: платформы и версии, точное время сбоев, тексты ошибок, что помогало (цитаты). Общее для всех клиентов — отдельно от единичного.
3. **Код.** Если рабочий каталог — репозиторий: `Grep` по строкам ошибок, именам модулей из логов, версиям; `Read` найденных мест; `git log --since` по затронутым файлам (подозрение на регресс после релиза — сверить даты с первыми жалобами). Если репозиторий не открыт — сказать об этом и остановиться на логах.
4. **Вывод** (до 40 строк): гипотеза (уверенность: высокая/средняя/низкая), где в коде (`файл:строка`), как воспроизвести, что ещё спросить у клиентов (готово для `/lumea:collect`), стоит ли заводить issue (`/lumea:issue`).

Ничего не отправлять и не менять.
