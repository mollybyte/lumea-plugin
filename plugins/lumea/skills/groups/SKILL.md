# Группировка открытых тикетов

Аргументы: `$ARGUMENTS` — проект (необязательно) и период по `lastMessage` (по умолчанию все открытые).

1. `export_tickets { limit: 200 }` (по умолчанию только открытые); без указанного проекта поле `projectName` не передавать вовсе, а не пустой строкой. Ответ MCP ограничен по объёму — `limit: 1000` за раз не пройдёт: брать по 200 и продолжать по `nextCursor`, пока не кончится или не набрано 5 страниц (1000 строк); если после 5-й страницы `nextCursor` всё ещё не `null` — сказать, что смотрели первую 1000, и предложить сузить проект или период. Оставить строки, у которых `lastMessage` попадает в период.
2. Сгруппировать по проблеме по `title`, `summary`, `tags`: одна группа — одна причина с точки зрения клиента («после обновления не подключается на iOS» и «на Android» — разные группы, если платформа названа). Тикеты, не похожие ни на что, — в «Прочее», без раздувания.
3. Для 1–2 представителей каждой группы из ≥ 3 тикетов — `list_ticket_issues { ticketId }`: есть ли issue (`issues.length > 0`).
4. Вернуть таблицу, отсортированную по размеру, с рефом каждого примера как `#` + первые 8 символов `id` (первая группа uuid):

| #   | Проблема                                                 | Тикетов | Без ответа | Платформа/версия | Issue | Примеры                         |
| --- | -------------------------------------------------------- | ------- | ---------- | ---------------- | ----- | ------------------------------- |
| 1   | iMac: браузеры и Spotify не через VPN, Telegram работает | 14      | 9          | macOS 13–15      | нет   | #1d2155aa, #7f3a02bc, #c091ee4d |

и одну строку: «Открыть кейс из группы N: `/lumea:case open <предложенный-slug> <refs…>`». Slug предлагать из 2–3 латинских слов через дефис.

Ничего не менять: только чтение.
