# Плагин `lumea` для Claude Code

Тикеты, клиенты, кейсы и issue Lumea прямо из Claude Code. Не «ещё один способ ответить на тикет» — встроенный AI Lumea делает это сам, — а работа с пластами: сгруппировать открытые тикеты по проблеме, вести общий дебаг с несколькими клиентами, собрать логи рядом с кодом, массово закрыть волну после фикса.

## Установка

```
/plugin marketplace add mollybyte/lumea-plugin
/plugin install lumea@lumea
```

Публичный маркетплейс `mollybyte/lumea-plugin` — зеркало каталога `plugins/lumea` этого репозитория, CI обновляет его после каждого деплоя по тегу (`plugin:publish`, скрипт `scripts/ci/publish-plugin.sh`); доступ к GitLab для установки не нужен.

Две обязательные переменные окружения: адрес Lumea (`LUMEA_URL` — схема и хост, без слэша и без `/api/mcp` на конце; адрес сообщает администратор) и ключ доступа (`LUMEA_ACCESS_KEY`: Lumea → Настройки → «Ключи доступа» → «Создать ключ», нужно право «Выпускать ключи доступа для MCP и API»). Положить в окружение:

```
export LUMEA_URL=https://<адрес Lumea>                                         # в ~/.zshrc …
export LUMEA_ACCESS_KEY=lmk_…                                                  # … или
"env": { "LUMEA_URL": "https://<адрес Lumea>", "LUMEA_ACCESS_KEY": "lmk_…" }   # в ~/.claude/settings.json
```

Адрес в плагин не зашит намеренно — домены меняются. В `.mcp.json` он подставляется как `${LUMEA_URL}/api/mcp` без значения по умолчанию: по документации Claude Code незаданная переменная без `:-default` не ломает загрузку плагина, но `claude mcp list` показывает предупреждение о ней, а в `url` остаётся литерал `${LUMEA_URL}` — сервер `lumea` не ответит ни одному инструменту, пока переменная не задана. Хукам плагина нужен `jq` (`brew install jq`): без него каждый пишущий вызов будет просить подтверждение с пометкой «jq не установлен»; монитору `/lumea:watch` — Node ≥ 18 (`node` на `PATH`). Если сервер Lumea уже добавлен вручную (`claude mcp add … lumea` из `docs/mcp.md`) — снять его (`claude mcp remove lumea`), иначе в сессии два набора одинаковых инструментов. Проверка: `/lumea:setup`. Обновление после релиза: `/plugin update lumea`.

## Что умеет

Просто разговаривайте: «что там с тикетом #1d2155aa», «кто сегодня жаловался на оплату», «напиши им, что чиним». Плагин знает модель данных Lumea и какой инструмент для чего. Горячие клавиши к процессам:

| Скилл                                                       | Что делает                                                                            |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `/lumea:setup`                                              | проверить адрес и ключ, показать права и доступные скиллы                             |
| `/lumea:groups [проект] [период]`                           | сгруппировать открытые тикеты по проблеме                                             |
| `/lumea:case open <slug> <тикеты…>`                         | открыть кейс (тег `case:<slug>` на тикетах); `add/remove/show/list/close`             |
| `/lumea:collect <slug> <что нужно>`                         | запросить логи у всех клиентов кейса, следить, кто прислал, скачать в `.lumea/cases/` |
| `/lumea:investigate <slug \| тикет>`                        | связать логи и переписку с кодом открытого репозитория                                |
| `/lumea:issue <slug \| тикет>`                              | issue в GitLab из кейса с проверкой на дубли                                          |
| `/lumea:resolve <slug \| #iid>`                             | сообщить всем, что починили; закрыть тикеты                                           |
| `/lumea:sweep <правило>`                                    | массовые действия по правилу на естественном языке                                    |
| `/lumea:digest [период]`                                    | сводка смены или суток                                                                |
| `/lumea:client <запрос>`                                    | карточка клиента, аккаунты, история                                                   |
| `/lumea:replies [list \| show \| new \| edit \| delete]`    | быстрые ответы: список, текст, правка и удаление с подтверждением                     |
| `/lumea:watch [case <slug> \| project <имя> \| all \| off]` | фоновые уведомления: новые тикеты, ответы и файлы клиентов                            |

Монитор `lumea-watch` хранит фильтр и курсор в `~/.lumea/` (переопределяется `LUMEA_WATCH_DIR`) — состояние общее для всех сессий на машине, поэтому активное наблюдение — одно на машину: вторая сессия с `/lumea:watch` перезапишет фильтр первой и поделит с ней курсор.

## Безопасность

Ничего не уходит клиенту и ничего не меняется без вашего «да»: хук плагина показывает адресатов и текст и спрашивает подтверждение на каждую отправку, блокировку, действие во внешнем сервисе, создание issue и правку быстрых ответов — даже в auto-режиме. Агенты `analyst` и `investigator` имеют только читающие инструменты. Права равны правам вашей роли в Lumea; на 403 плагин говорит, какое право попросить у администратора.

## Разработка

```
claude --plugin-dir plugins/lumea     # локальная загрузка
bunx vitest run plugins/lumea          # статические проверки
claude plugin validate plugins/lumea   # схема
claude plugin eval plugins/lumea       # поведение, на моках (платно)
```
